## Architecture rules
- Graph code lives in `src/graph/` (data loading, force layout Web Worker, demo seed, R3F scene); keep it isolated so UI edits don't break it.
- The 3D scene is lazy-loaded client-side only (`React.lazy`) because three.js/WebGL can't run during SSR.
- Initial graph load fetches only lightweight fields (id, title, type, weight, cluster, positions, edges); full note content loads on click — keeps payload small for thousands of notes.
- Saved positions (pos_x/y/z) are reused; only notes without positions get laid out, with existing ones fixed — stable layout.
- Server-side AI logic uses authenticated TanStack server functions (not Edge Functions), with providers confined to server-only modules to protect credentials.
- Generative AI runs on Groq (open-weight `openai/gpt-oss-120b` for answers, `openai/gpt-oss-20b` for short tasks) via `src/ai/groq.server.ts`, keyed by the `GROQ_API_KEY_SINAPSI` secret. Do not reintroduce the Lovable AI gateway. Every call counts against `graph_settings.daily_ai_cap` (default 200/day) in `ai_usage`.
- Embeddings are computed on-device in `src/ai/embed.worker.ts` (Transformers.js loaded from a pinned jsDelivr build, model `Xenova/multilingual-e5-small`, 384 dims). They are zero-padded into the existing `vector(768)` column, which preserves cosine similarity, so no migration is needed. Tunable thresholds live in `src/ai/config.ts`.
- The semantic pipeline (`src/ai/pipeline.ts`, driven by `usePipeline`) runs in the browser: notes with `ai_status = 'pending'` get a vector, up to 5 `semantic` edges from `match_notes`, a content-based `weight`, and the constellation of their nearest neighbour. Constellations (k-means, ids from 10 up so they never clash with demo clusters 0–5) are recomputed as the memory grows; names come from Groq, hues are spread by golden angle and stored in `clusters`.
- Private notes are embedded and linked locally, but their content is never sent to Groq (chat answers, constellation names and connection explanations all skip them).
- The AI chat is RAG-only: local query vector + full-text retrieval, then a cited answer; with no relevant notes it says so without calling the model.
- Note CRUD and text search live in `src/notes/`; archive operations validate a versioned portable ZIP before a transactional restore to preserve graph relationships.
- The graph renders continuously so neurons can float, breathe and send pulses along synapses (falls back to on-demand rendering with no motion when the user prefers reduced motion). Camera motion stays user-driven, except the login background which rotates slowly. The force layout pulls each constellation towards its own anchor.
- Neurons, halos, synapses and background dust are custom shaders in `src/graph/shaders.ts`; all share the same `drift()` so synapses stay attached to floating neurons. Picking uses the static instance positions. Bloom and vignette come from `@react-three/postprocessing`.
- 3D labels are plain DOM nodes positioned by `LabelProjector` each frame (no drei `Html`, which mounts extra React roots and crashed on unmount).
- Mobile: safe-area insets, 16px inputs (no iOS zoom), one-finger rotate on touch, constellation chips under the header.
- Auth: email + password by default (sessions persist in localStorage), magic link and Google as alternatives; accounts created via link can add a password from the ⋯ menu.
- Phase 2's "latest 100 notes" AI search has been replaced by the Phase 3 RAG search above.
- Attachments (Phase 5) live in the existing `sources` table (`folder` = note id, `uri` = storage path or URL, `extracted_text` = what the AI can read) and in the private Storage bucket `attachments`, created on demand. Storage is touched only server-side with the service role, always scoped by the `<userId>/<noteId>/` path prefix checked in `src/attachments/kinds.ts`; clients upload through signed upload URLs and view through signed URLs. No Storage RLS migration is needed.
- PDF and text files are read in the browser (pdf.js legacy build from jsDelivr); images go to Groq's vision model and audio to Whisper on Groq, links are fetched server-side and summarised. None of this is sent to Groq for private notes.
- The attachments' text is concatenated into `notes.enriched` (full-text indexed) and the note is set back to `pending`, so files take part in embeddings, synapses, constellations and the RAG chat. Deleting a note first purges its attachments (no foreign key).
- Imports (Phase 6) live in `src/import/`: parsers run on-device (WhatsApp .txt/.zip, vCard, LinkedIn Connections.csv, .ics), runners in `run.ts` write through the user's session. Imported notes get deterministic ids (`stableId`, SHA-1 of user + key) so re-importing never duplicates. WhatsApp: one note per conversation (pauses > 8h, max 40), transcript kept as a `sources` row (`uri` `whatsapp://…`), optional Groq summary per conversation; without AI the notes are private. People and groups are private `persona`/`gruppo` notes; `person` and `thread` edges are added with ignoreDuplicates so semantic edges are never overwritten.
- Calendars: a linked iCal URL is a `sources` row with `kind = 'calendar'` (`extracted_text` holds `{lastSync, name}`); `syncCalendars` runs when the app opens, at most every 6 hours, fetching through the `fetchCalendar` server function and updating only changed event notes (`type = 'evento'`).
- Proactive brain (Phase 7) lives in `src/brain/` and uses the existing `jobs` table, no migration: `kind = 'reminder'` (status open/done/dismissed, `run_after` = due, `payload` = `ReminderPayload`), `kind = 'digest'` (one weekly summary, cached), `kind = 'scan'` (hash of a note's text, so unchanged notes are not re-read). After the pipeline embeds notes, `scanNotes` calls `extractIntents` (Groq, skipped for private notes, demo, events, people, conversations, projects, and texts without date/plan cues); missing deadlines are searched with Groq's `browser_search` tool (`lookupDeadline`). WhatsApp commitments become reminders at import time.
- Phone notifications come from a private iCal feed: `src/routes/api/promemoria/$token.ts` (server route, service role) maps a 48-hex token stored as a `sources` row of kind `reminder_feed` to the user's open reminders. The app also shows a bell with due/overdue counts and one browser notification per day if allowed.
- The AI chat is multi-turn: up to 3 previous question/answer pairs are sent as context, still answered only from notes.
- Connectors (`src/connectors/`): `syncConnectors` runs on app open (calendars + GitHub, each at most every 6 hours). GitHub accounts are `sources` rows of kind `github` (`uri` `github:<login>`, `extracted_text` JSON with optional read-only token and the `pushed_at` seen per repo). Each non-fork repo is a `progetto` note (stable id from the repo id; private repos → private notes) whose README is a `sources` text row (`github://…/README`); notes mentioning the repo by name get `project` edges. GitHub is called from the browser, so the rate limit is the user's (60/h without token). Archive exports drop `github`, `calendar` and `reminder_feed` sources so secrets never leave.
- Scale and rendering (Phase 8): synapses are screen-space ribbons (indexed quads, `aSide` pushed sideways in the vertex shader, width in pixels from strength), built once per graph; focus and search only rewrite the per-vertex `aState` (0 normal, 1 dimmed, 2 highlighted). Halo colours update in place. `densityOf(nodeCount)` dims halos, synapses and bloom and shrinks neurons on large graphs (additive light saturates otherwise); above 1500 neurons or on touch devices spheres use fewer segments, above 4000 edges ribbons use 8 segments. Level of detail: one `Nebulae` sprite per constellation fades in from afar, constellation names fade out up close, and `LabelProjector` names the ~10 nearest visible neurons (recomputed every 6 frames).
- Installable/offline: `public/manifest.webmanifest`, icons and `public/sw.js` (network-first for pages, cache-first for hashed `/assets/`; never caches server functions, `/api/` or other origins). The service worker is not registered in development or inside the Lovable editor preview. `src/lib/offline.ts` keeps an IndexedDB copy of the graph, the notes list and opened notes (`withOffline`), shown with an offline banner when the network fails; cleared on sign-out. The AI pipeline does not run while offline.
- `VITE_EMBED_LIB_URL` can override the Transformers.js URL (used for tests with a fake model or for self-hosting).

- Email verification: `src/routes/index.tsx` and `/admin` show `VerifyEmail` (resend link / use another email) until `session.user.email_confirmed_at` is set. The real gate is Lovable Cloud's "Auto-confirm email" switched off; the screen is a second line of defence.
- Admin (`src/admin/admin.functions.ts`, route `/admin`): admins are the comma-separated, verified emails in the server secret `SINAPSI_ADMIN_EMAILS` (never written in the repo). `adminOverview` lists auth users with the service role and returns counts only (real notes, edges, last activity, AI calls in 30 days), never note content. The ⋯ menu links to `/admin` only when `amIAdmin` says so.
- Onboarding (`src/components/Onboarding.tsx`): a timed, skippable story over a local demo brain (`buildDemoGraph`, nothing written to the database) shown once per account (`user_metadata.onboarded_at`, plus a localStorage flag). While it runs the main GraphScene is not mounted (the scene's size scale is global, two scenes must never render together). At the end any demo notes in the database are cleared and a toast says the demo comes back from ⋯ → Carica demo; ⋯ → "Rivedi l'introduzione" replays it.
